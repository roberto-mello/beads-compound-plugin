# Lavra v0.7.8 Release Notes

**Release date:** TBD

---

## Improvements

### Sequential mode for epics

Working through an epic used to mean one thing: parallel subagents, one per bead, burning tokens fast. That was fine for large epics where parallelism actually helped, but overkill for a three-bead task.

Now when you run `/lavra-work` on an epic with multiple beads, it asks how you want to work:

> **3 beads ready. How do you want to work?**
> 1. Sequential — work beads one at a time in this context. Lower token cost. Review runs once at the end.
> 2. Parallel — dispatch subagents per bead simultaneously.

Sequential mode loops through each bead using `lavra-work-single` directly, no subagents. Review runs once after all beads complete rather than after each one. For small-to-medium epics, that's meaningfully cheaper.

Pass `--parallel` to skip the question and go straight to subagents. Pass `--no-parallel` to always go sequential.

### Review findings: fix small things inline

After a review pass, not every finding needs a bead. A typo in an error message, a missing `freeze` on a constant, a redundant nil check -- creating a bead for each of these wastes more time than fixing them takes.

`lavra-work-single` and `lavra-work-multi` now triage review findings before acting on them. P3/cosmetic findings that touch a single location already in context get fixed inline. P1/P2 findings, anything multi-file, and anything requiring new reads still become beads as before.

The review gate checklist now tracks inline fixes separately so nothing falls through the cracks.

### `lavra-work` is now a skill

The router logic that was in `commands/lavra-work.md` moved to `skills/lavra-work/SKILL.md`. The command is now a one-line shim. Other skills (like `lavra-plan`) can invoke it directly without going through the command layer.

### `/lavra-design` research gate is now token-explicit

The Phase 2 gate in `/lavra-design` now calls out that research can be expensive in tokens before running domain-matched research agents across child beads.

It now presents explicit choices:

1. Skip research (default gate option) and continue to revise/review
2. Run research + review (higher token cost)
3. Adjust plan first
4. Stop here

Config defaults stay unchanged: `workflow.research` in `.lavra/config/lavra.json` still defaults to `true`. Set it to `false` to always skip the research phase unless you opt in at runtime.

### Deferred anti-patterns now require a durable record

When an agent finds a recurring wrong pattern but leaves it out of scope, a deviation comment used to be the end of the story. Future agents would never see it.

Now `lavra-work-single` requires one of two things before moving on: a `MUST-CHECK` knowledge entry (so the warning surfaces in auto-recall next time someone touches that area), or a proposed addition to the project's agent rules. A deviation comment alone no longer satisfies the gate.

### Cleaner knowledge, better recall

Auto-recall is only as good as what's in the knowledge store. Over time, entries accumulate duplicates, stale facts, and broken anchors. When those surface during recall, agents act on outdated information -- or miss the entry that would have caught a bug.

Lavra now runs a background cleanup pass on `knowledge.jsonl` after each session. It deduplicates entries, validates anchors, flags drift, and generates an audit trail. The result: recall returns the right entries, not just recent ones.

If `go` is available, Lavra compiles a local binary in `.lavra/memory/` and uses it for the full pass. If not, a reduced fallback runs instead. Either way, recall keeps working.
